## 代码口头交接

浏览器`app.js`提交JSON；`server.py`检查路由、来源和请求大小；`service.py`校验资料和生成参数；`generator.py`作三段摘录或一次模型请求；`store.py`持久化SQLite资料、Markdown和所选资料快照。报告引用编号按所选ID顺序分配。模型非正常完成、接口超时或未配置时返回错误，当前没有自动重试。`[S1]`只负责定位输入，不能证明事实受到来源支持。

可据此练习四个问题，并用代码和实际运行结果逐项核对：

| 问题 | 应说明的事实 |
| --- | --- |
| 一次生成经过哪些模块？ | 页面提交所选资料ID；服务层校验并读取完整资料；生成器返回Markdown与警示；存储层保存报告和当次资料快照。 |
| 为什么下载后仍能查到当时资料？ | `Store.add_report`把所选资料写入`sources_json`；报告详情读取的是这份快照，不依赖后续资料列表。 |
| 模型请求失败会怎样？ | 未配置、接口错误、超时、截断或非`stop`结束时返回错误；`Service.generate`不会调用`Store.add_report`，也不会自动重试或冒充摘录结果。 |
| `[S1]`能证明观点正确吗？ | 不能。它只对应本次选中的第一份输入；数字、单位、时间和观点支持关系仍需人工回查原发布页面。 |
