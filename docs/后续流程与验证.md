# 后续增加的流程与验证

基线先支持一次请求生成报告，复杂流程不提前承诺已完成。建议后续按以下顺序添加，并由长期认领人负责。

1. 增加有编号的任务与步骤状态，将资料准备、提纲、章节、审阅、导出拆开。明确每步输入版本和产物保存条件。
2. 增加检查点与约定边界恢复，区分已完成产物和状态不明的外部调用。重复调用可能再次付费，需验证而非默认恰好一次。
3. 加入错误分类、有限重试、超时和调用预算，记录真实用量及成本估计误差。
4. 引用与版本门禁、人工审核、章节局部修订、图表与正式格式导出。
5. 建立有来源的真实产业评测数据，分别测检索、引用定位、内容支持、完整流程、故障恢复和耗时成本。
6. 对照同输入、模型、版本和任务条件比较基线与Harness。结论由实际结果支持，记录额外控制带来的开销。

现有12个测试用于检查基线功能和错误处理，不代替上述业务评测，也不代替课程系统测试报告。真实模型联调、产业样例、课堂概念应用和用户试用均需后续记录。
