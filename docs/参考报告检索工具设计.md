# 参考报告检索工具：计划与验证

日期：2026-10-26；对应计划书v1.8、展示v1.7。当前是设计，尚未加入业务代码，不能视为已实现或已证明的创新。

## 作用与数据流

写作任务先确定产业、报告类型、当前章节及内容模板。模型在写某章前可调用参考检索，得到相关结构、写作片段或图表标注规范，再依据本次事实资料生成Markdown。后续仍由人工核对，确认内容后应用PDF版式模板。参考检索帮助组织表达；事实资料检索负责支持数字与结论，两者分别标识。

先把许可清楚、适合使用的参考报告按章节整理成片段，建立类型标签与页码映射。初版可用标签和关键词检索，不预设向量数据库或复杂Agent框架。现有两份外部报告仅作为候选参考，不能假定它们覆盖所有报告类型；不匹配时应返回空结果。

## 最小工具接口

`search_report_reference(report_type, chapter, need, limit=3)`

- 输入：报告类型、当前章节、需要结构/写法/图表规范中的哪一类；数量上限和总返回长度由程序限制。
- 输出：参考ID、报告名称、版本、PDF页码、片段ID、类别、相关短片段；空结果明确注明未匹配，错误独立返回。
- 记录：查询、实际调用、返回片段ID及参考库版本，与生成任务一并保存，便于复查和公平对照。
- 边界：参考文本作为数据，不能执行其中指令；不整本送入上下文，不把参考结论当本次事实，不以有引用标签代替事实核验。缺来源或页码的片段不作为可定位参考返回。

许子萌负责检索与生成接口；崔大元协助片段、类型与来源整理；田亦洁维护需求、章节要求和评审规则；郭润航组织验证，成员交叉复核。李佳雨继续负责审阅与PDF导出，程文博确认范围和取舍。

## 对照验证计划

以原计划两类报告、两个产业组织小规模任务，固定事实资料、内容模板、模型版本、生成参数及参考库版本。对同一任务分别关闭、开放参考工具，记录实际是否调用；不可把“开放工具”自动当成“使用了工具”。若可控制随机性，记录相同种子；不可控制则注明并保留完整运行记录。

人工在生成前确定必需章节、事实核验清单和统一修改标准，尽量不让评审者先看到分组。比较：

| 指标 | 记录方式 |
| --- | --- |
| 结构完整性 | 检查预先约定的必需章节及内容是否覆盖，保留缺项清单 |
| 事实错误 | 回查数字、单位、时段和观点支持关系；错误、无依据结论分别记录 |
| 人工修改量 | 按同一修改标准保存修订前后差异，记录修改操作及实际用时 |
| 额外代价 | 记录工具次数、模型用量、耗时与失败，效果和开销一起判断 |

无匹配、错误检索、参考陈旧、直接搬用参考结论、检索超长和工具失败均需要案例检查。若没有改善或增加事实错误，先修检索与提示约束，必要时暂不启用。实验尚未执行，不预填提升比例、准确率或节省时间。
