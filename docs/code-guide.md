# 光伏研究工作台接手指南

## 运行与检查

[README](../README.md)有本地启动和 PDF 导出命令。网页首页是光伏研究工作台。先用离线样例核对 Markdown、审阅和导出，再配置本机模型跑联网案例。

离线简报用 LangGraph 运行检索、补查和写作节点。联网长报告由 Python 按阶段调度，用 SQLite 保存断点。[中期验证记录](../presentations/02-midterm/evidence/README.md)里的 DeepSeek Harness 和 Pi CLI 试验分别用本机模拟模型调用同一只读检索工具。

## 组内演示

1. 进入首页，选择「直接写报告」。在「范围与篇幅」填 1150 字，限定「国家统计局规上工业月表」。
2. 输入「比较 2025 和 2026 年 10 月及 1—10 月的光伏电池产量。逐项列出原表发布量和可比口径同比，说明两年的发布量为什么不能直接用来重算同比。」
3. 报告完成后，先点 2026 年 10 月产量旁的编号，检查统计范围和原始出处。打开「生成过程」查看取数和复核记录，确认后下载 PDF。该题的样张保存在本机验收样张目录。

## 从提问到 PDF

| 步骤 | 代码位置 | 数据变化 |
| --- | --- | --- |
| 确定范围 | `Research.start_long`、`long_report.make_plan` | 接收问题、读者、地区、年份、篇幅、章名和资料选择。「先聊一聊」保存讨论，在用户确认后启动。「直接写报告」立即规划。 |
| 联网取数 | `SolarLibrary.collect`、`ingest` | 从登记的发布页和接口读取数据，按发布方、统计期、指标和单位写进 SQLite。用户指定资料时只访问对应来源。 |
| 逐章写作 | `long_report.choose_evidence`、`write_part` | 给每章选同口径的跨年记录和原文段落。模型返回带证据编号的段落，程序核对编号、数值和单位。 |
| 复核与排版 | `long_report.review_scope`、`assemble` | 按证据检查年份、地域、指标、因果和适用范围，从核过的正文选摘要。附表读取观测值，图按附表生成。 |
| 下载与确认 | `Research.task`、`Research.approve`、`pv_brief.py` | 网页展示正文、引用和生成过程。Markdown 与证据 JSON 可直接下载。用户核对后确认并导出 PDF。 |

分省计算工具有两条入口。网页传入用户选择的期间、指标和地区；普通研究由 `infer_comparison` 检查用户原话是否明确给出同一组参数。参数含糊时继续原有研究流程。`build_comparison` 从已核对指纹的 CSV 取两期数值，用十进制计算差额与名次。`Research.create_comparison` 在同一笔 SQLite 事务中保存正文、计算记录和历史条目。`calculation_evidence` 把这份冻结结果交给后续写作，`reconcile_comparison` 用两期排位复核模型写出的比较句。正文中的计算引用可回到两期原表。[演示及离线复算](分省数据对比.md)

对一条数字，可以从报告正文点开证据编号，核对证据的地区、时间、单位、原发布地址和内容指纹。资料库按地区、年份、指标和机构筛选，可下载原始精度的 CSV。证据 JSON 包含本次 Markdown 下载内容的 SHA-256，用于核对两个文件是否来自同一稿。

## 资料怎样入库

- `solar_sources`记录发布页、实际取数地址、发布时间版本对应的内容指纹和本次访问时间。`solar_observations`存地区、年份、指标、单位和原始数值。`solar_passages`存可定位的原文段落或 PDF 页码摘记。
- 分省年表、上半年表与前三季度表分别解析。国家统计局月表将发电和光伏电池产量按单月、累计各自入库。1—2 月保留为合并期，原表同比单列。光伏利用率保留统计分区。欧洲进口按原产地和欧元统计，完整月份才能生成窗口累计。
- 同一地址发布内容更新时另存快照。解析补列时可使用新的内部解析标识，旧报告仍可查到生成时的值。套用旧快照时记录原因。
- 对照样张与取数出处见[迭代记录](光伏工作台迭代记录.md)、[国家能源局数据说明](../code/data/nea/README.md)和 [IRENA 数据说明](../code/data/irena/README.md)。

## 中断和回查

| 情况 | 工作台行为 |
| --- | --- |
| 来源访问失败 | 尝试已取得的匹配快照，并在取数记录说明使用的版本。关键证据缺失时提示调整问题。 |
| 章里出现无依据的数字 | 先要求模型更正，仍无法核对时用可定位的事实句打底。复核会删掉无法支持的解释。 |
| 写作超时或服务重启 | `long_jobs.checkpoint`保存提纲、证据和已完成章节。重新打开同一任务可继续。任务租约阻止重复写入，重启前正在执行的步骤单列为中断。 |
| 需要核对模型调用 | 打开「生成过程」或下载证据 JSON。记录各阶段耗时、模型请求数和服务商返回的用量。 |
| PDF 排版失败 | Markdown 草稿仍可下载。检查 Typst 环境后重新确认导出。 |

数值和单位检查可以发现引用没有提供某个值，年份与地区的对应关系仍需审查。产业推断也需要回到原始材料和人工核对。模型密钥保存在本机 `code/.env`，提交代码或分享验证材料时只提供公开来源及生成结果。
