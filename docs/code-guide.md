# 基线代码解释与接手指南

## 架构

基线使用Python标准库：ThreadingHTTPServer提供本地HTTP接口，SQLite持久化资料和报告，静态HTML/CSS/JavaScript提供工作台。没有第三方业务运行依赖，也没有队列、Harness或前后端构建链。

浏览器提交JSON，server.py检查请求边界，service.py校验字段和资料ID，generator.py生成摘录或调用配置的模型，store.py保存报告和所选原文快照。浏览器显示草稿、警示、来源原文和下载入口。

## 关键函数

- Store.add_source / get_source：保存和获取原文。SQL使用参数绑定，避免将输入拼进语句。
- Service.generate：校验主题、模式与资料ID，读取完整资料，选择生成模式，成功后保存报告。
- excerpt_report：每份资料取前3个非空段落，附[S1]等标记。这是确定性的文本摘录，不是语义检索或产业推理。
- model_report：一次同步POST，发送model和messages，读取choices[0].message.content。正文总量超限、服务错误、超时、无效响应或截断时明确失败，没有隐式重试或摘录回退。
- Store.add_report：保存Markdown、原文快照及警示，来源标签顺序对应用户本次选择。
- make_server：仅绑定127.0.0.1，静态文件使用固定允许表，接口响应不传出模型密钥或供应商错误正文。
- app.js：所有外部文字使用textContent渲染，保持Markdown原文，不将模型输出直接作为HTML执行。

## 数据流与边界

录入真实来源元数据和正文，选择最多10份资料，输入主题后生成。摘录模式完全离线；模型模式需显式配置，原文会发给所选服务。资料URL仅存储，不自动抓取。资料没有自动更新，报告保存快照保证之后仍可查看当时输入。

原文摘录只证明复制了哪些输入，来源标记仅能定位资料。代码没有证明来源权威、观点正确、数字一致或产业判断成立。人类需要核对。输入语料总长限制不是token预算模型，后续再加入真正检索和上下文预算。

## 失败模式

| 情况 | 当前行为 | 后续方向 |
| --- | --- | --- |
| 空资料、重复或不存在的ID | 返回输入错误，不生成报告 | 更完善表单与文件解析 |
| 模型未配置 | 明确报错，不回退成假模型结果 | 团队选定服务后真实联调 |
| 超时、HTTP错误、截断 | 返回脱敏错误，当前无自动重试 | Harness分类重试与调用约束 |
| 进程中断 | 已保存资料/报告保留，正在生成的请求不恢复 | 任务状态、步骤检查点与恢复 |
| 无引用或引用越界 | 标为警示，保留草稿供人工修订 | 引用门禁和人工审批 |
| SQLite失败 | 返回存储错误 | 迁移、备份、并发及运维策略 |

本地服务没有认证和多用户权限，作为课程开发基线运行。公开部署和新增外部数据操作须增加相应设计。

## 接手步骤

T5先跑服务与测试，逐段解释以上数据流，再用合法真实产业资料替换构造样例，记录实际输入输出。检查一例正常流程和一例失败流程，修改自己不能解释的代码。记录AI辅助内容、人工改动及核验，不能把初始化代码自动计为成员已经完成的个人贡献。
