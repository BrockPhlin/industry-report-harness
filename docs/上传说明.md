# 上传与团队协作

本协作目录独立对应仓库 https://github.com/BrockPhlin/industry-report-harness 。仓库根目录包含code、team、presentations等内容；父目录的历史稿和其他桌面项目不属于本仓库。成员通过git clone获取，保留.gitignore、.github和预留目录中的.gitkeep。

远程仓库已由程文博创建；成员邀请由组长管理。老师课件按其允许的共享范围处理。

## 第一次协作

1. 当前开题安排已记录在team/claims.csv；学期职责见team/长期分工.md，调整负责人由组长确认，不能把任务安排当作实际贡献。
2. 报告在presentations/01-opening/report修改，PPT在对应ppt修改。二进制PPTX由认领人统一整合，避免多人同时覆盖。
3. 中期与终期目录仅预留，后续按当时实际要求填写。
4. 每个任务使用独立分支，提交具体产出、检查和待完成项，另一人审阅后合并。
5. 不上传code/.env、SQLite、运行日志、私有资料或未经允许的课件。gitignore已包含常见运行产物。

## 源码与直接编辑

报告Markdown与slides.json是可重复构建的源文件，PPTX也是可直接编辑的交付源。如果直接改PPTX，记录这次以PPTX为准，避免之后运行生成器覆盖手工修改。若需保持JSON与PPTX一致，由PPT认领人在后续整理变更。

## 记录边界

成员认领、实际工作与AI初始化分开。开题任务已安排、老师P4/P5已建立页码映射；这些是计划与本次材料核对结果，不能把模板当作真实会议、课程引用或成员履约记录。

## 六人共同维护的执行约定

组长于2026-10-26提供的GitHub权限截图显示5个协作者账号，加上仓库所有者，作为共同维护入口。截图与说明见team/collaboration-evidence.json。账号与姓名没有逐一核对，不根据头像推断个人贡献。

1. 按既定分工在任务表或Issue写清产物、负责人和完成条件。
2. 先同步main，再在个人任务分支修改代码、报告或幻灯片源码；每次提交说明具体改动。
3. 提交PR写清变化、检查结果与遗留问题，安排另一位成员交叉检查；作者处理意见。
4. 组长核对范围、验收及版本后合并，其他成员拉取更新。此为协作约定，不宣称已配置强制分支保护。
5. PPTX由李佳雨整合；文档与代码一起更新。每周按任务产物、评审和测试记录检查进度，不把提交次数直接当贡献分。

已有PR #5合并代码完善、PR #6合并课程资料，均可从仓库历史核对；后续每次评审、会议和测试按实际发生留记录。
