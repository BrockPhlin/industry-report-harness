## 1 项目目标与范围

### 1.1 用户、场景与问题依据

项目面向需要整理公开资料、撰写产业研究简报的学生和研究助理。用户将多份资料录入系统，选择本次写作使用的来源，系统据此生成带来源标记的草稿；用户核对原文、修改内容后导出报告。

写作过程中，资料需要统一整理，章节中的数字和观点需要回到原文核对。生成任务中断后从头执行还会造成重复工作。系统保存输入版本、来源快照和生成步骤，让使用者能够定位依据，并从已有结果继续处理。

### 1.2 范围与交付策略

| 层级 | 内容 | 验收边界 |
| --- | --- | --- |
| 学期核心 | 使用一组公开产业资料生成一种主报告；支持资料管理、分步生成、来源定位、人工审阅、版本和正式导出 | 用同一组合法公开资料完成“录入—生成—核对—修订—导出”，产物与来源快照可追踪 |
| 当前基线 | 文本资料录入、SQLite保存、确定性摘录、可配置模型适配、历史、来源快照和Markdown下载 | Python 3.10以上本地启动；模型未配置或调用失败时明确报错 |
| 条件扩展 | 多模板、章节局部修订、自动检索和更多图表 | 核心验收完成后，根据数据许可、时间和费用决定是否开发 |
| 暂不开展 | 全产业覆盖、底层模型训练、无人审核发布、复杂多Agent调度 | 不纳入本学期范围；未经核对的预测不作为报告结论 |

项目先完成一条可核对的完整流程。通用聊天工具通常只返回一次性文本，本系统还会保存输入版本和来源快照，记录生成步骤及失败状态，并保留人工修订版本。模型输出经过来源核对后才能发布。

### 2.1 非功能目标

来源标签用于定位原文，观点、数字和单位仍由成员核对。外部调用设置超时、有限重试和费用上限，状态不明时不重复发起付费请求。本地服务默认绑定127.0.0.1，密钥、个人信息和受限资料不进入仓库；资料发送到模型服务前检查使用权限。需求、设计、实现和测试使用统一编号。性能按代表性资料的规模和实际运行环境测量，不预设没有测试依据的速度或准确率。

### 2.2 需求确认与变更

程文博组织团队确定演示使用的公开资料、目标简报和非功能指标。具体产业随资料确定，用于验证流程，不限制系统只能服务该产业。范围变化记录原因、影响、处理决定、负责人和版本；交付范围、费用或里程碑发生变化时同步调整计划。

# 3 技术方案与可行性验证

### 3.1 架构与数据流

浏览器向本地HTTP接口提交资料，Server限制路由和请求边界，Service校验主题、模式与资料ID，Store使用SQLite保存资料和报告。生成时读取所选原文，Generator执行确定性摘录或一次兼容Chat Completions的模型调用，成功后保存Markdown、警示和来源快照，前端展示历史、原文并提供下载。

| 层次 | 当前实现 | 学期实施重点 |
| --- | --- | --- |
| 资料层 | 文本、来源元数据、SQLite持久化 | 合法公开样例、文件解析、资料版本与质量检查 |
| 生成层 | 确定性摘录、单次模型适配 | 提纲与章节任务、上下文预算、引用检查和幻觉抑制 |
| 业务层 | 报告历史、快照、Markdown下载 | 人工审阅、版本、图表及PDF或DOCX导出 |
| 执行层 | 同步请求，错误显式返回 | Harness步骤状态、检查点、恢复、有限重试和调用上限 |

### 3.2 技术选择与依赖

基线采用Python标准库、SQLite和原生HTML/CSS/JavaScript，减少新环境的启动成本；材料构建使用ReportLab、Pillow和pypdf，与业务运行依赖分开。模型通过Chat Completions兼容接口接入，服务商按数据使用条件、价格、超时和输出格式选择。PDF解析、图表和正式导出先用小样例检查中文、表格和分页，再选择实现库。

### 3.3 已有验证与后续验证

2026-10-22在Python 3.13.5环境复核基线测试，12项通过、0失败、0错误，覆盖SQLite重开、输入校验、来源顺序、模型未配置、供应商错误脱敏、截断输出、本地HTTP生成下载和静态路径边界。该结果证明当前基线代码在本环境通过既有测试，不证明真实模型质量、产业结论正确或完整Harness可用。

后续按“模块测试—接口联调—真实任务流程—故障恢复—业务抽查”推进。每次测试记录软件版本、环境、输入来源、步骤、预期、实际结果和证据位置；失败和遗留问题如实保留。
