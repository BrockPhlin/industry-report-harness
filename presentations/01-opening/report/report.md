# 1 课题背景与课程依据

本项目对应P4第7页的课题2，面向政府智库、产业规划和行业研究，开发模板化、结构化、可溯源、可定制的报告生成引擎。拟提高撰写效率，规范章节结构，使正文与数据对应。首轮用公开资料验证；选题需求与实际收益仍待核实。

### 1.1 从课堂方法形成项目安排

| 课程依据 | 方法要点 | 本项目采用方式 |
| --- | --- | --- |
| P4第24、32、43页 | 滚动计划、责任矩阵、三级WBS | 项目—工作包—可验收子任务；执行、评审、确认分别落实 |
| P5第6页 | 以报告系统讲功能划分 | 按资料、模板、生成、审阅、导出划分任务并检查覆盖 |
| P5第17—21、28页 | 依赖、甘特图、关键路径、里程碑 | 用进度图找串行链与可并行工作，按产物检查完成情况 |

上节课学长关于Harness的分享提供了步骤管理、状态记录和任务接续的思路。技术细节依据[R1—R3]核对，课堂分享另见课程映射，两者分别注明来源。

### 1.2 目标与范围

模板体系面向产业分析、景气、对标、招商和出海研判五类报告。功能包括模板管理、提纲及分章生成、数据嵌入与自动图表、观点溯源、公文风格润色、Markdown与多版式PDF导出，以及版本管理。本期以产业分析、对标两类报告及两个产业验收完整流程，其余三类逐步扩展。底层训练和无人审核发布不纳入本期。

资料、模板与业务流程分别管理，产业案例用于验证系统，不限定系统服务的产业。内容模板规定章节，版式模板规定PDF排版；具体章节和样例仍需核实需求后确定。


### 1.3 在实践中形成创新

本项目拟开展参考报告检索试验。模型在写作前查阅结构与写法，事实仍以本次资料为依据；对照有无工具的结构完整性、事实错误和人工修改量，再据实测结果判断方法是否有效。

# 2 一个可核对的产业简报场景

以用户整理“2024年光伏产业简报”为例，资料来自制造运行、能源装机等来源。报告需要区分指标对象、年份和单位，关键表述应能回查原文。

![图1 2024年光伏组件产量与价格同比；依据D1人工整理，不是模型输出](../../../assets/opening/pv-example.png)

工信部披露，2024年光伏组件产量588GW，同比增长13.5%，组件价格同比下降29.7%[D1]。国家能源局披露，同年光伏新增装机2.78亿千瓦，换算为278GW[D2]。制造产量与新增装机不能混写，也不能仅凭产量增长判断利润增长。

### 2.1 预期输出与检查

事实陈述和图表均保留年份、对象、数值、单位及来源。若出现“新增装机588GW”，应回查原文并纠正。此例由人工设计，不作为模型评测结果。

第二个候选产业为新能源汽车，使用工信部2024年产销资料[D3]检查口径。两个产业各补足至少3份许可清楚的公开资料，历史数据注明时段，不作为当前最新数据。

### 2.2 用户操作

用户导入资料后，按模板生成报告，核对原文并修订，确认后导出。当前原型仅支持录入、摘录、来源快照与Markdown下载；截图未调用模型，真实用户任务及跨产业效果仍待验证。

# 2.3 两份参考报告分析与成品目标

两份外部报告用于参考内容组织与PDF呈现，不是本组生成成果。下图沿用PPT中的原始页面，保留原PDF及印刷页码。

| McKinsey参考页 | Stanford参考页 |
| --- | --- |
| ![McKinsey PDF第13页](../../../assets/references/mckinsey-2026-page13.png) | ![AI Index PDF第20页](../../../assets/references/ai-index-2026-page20.png) |

### McKinsey《Technology Trends Outlook 2026》[R4]

报告按技术主题设置目录，单独说明研究方法；示例页同时呈现指标、趋势解读和后续发展。拟据此设计内容模板，统一同类章节结构，使指标与解释对应。观察位置：PDF第3、5、13页，对应印刷第1、3、11页。

### Stanford《AI Index Report 2026》[R5]

报告设有总目录和章内目录，示例页列明图表标题、编号、数据来源及备注。本项目参考其标注方式，使指标口径和来源便于核对。观察位置：PDF第2、14、20页，对应印刷第1、13、19页。

### 落到本系统的目标

正文、表格、图表引用和来源标记以Markdown保存。内容模板规定章节，版式模板控制字体、目录、页眉页脚及分页。同一确认稿分别导出研究版与简报版PDF，两版的事实和引用保持一致。

参考报告检索工具按当前章节返回相关结构、少量写法片段与图表规范，并附报告名称、页码及片段ID。参考内容用于借鉴表达，当前事实由本次资料支撑。两份报告不能覆盖所有报告类型；未匹配到内容时应提示，不生成虚构的参考结果。工具效果仍需通过有无工具的对照验证。

本项目不照搬机构标识或分析结论，也不承诺相同篇幅、数据规模和研究能力。原文件由组长提供，文件指纹与预览位置见materials/references/output-report-targets.json。

### 3.1 非功能与数据边界

本地服务绑定127.0.0.1。密钥、运行数据库和受限原文不提交；向模型发送资料前核对许可。输入量与上下文限制先用样例验证。模型调用异常时明确报错，不将摘录作为生成成功的结果。

引用标签用于定位资料，内容是否正确仍需核对。缺少支持材料的观点标记为资料不足，不提供未经验证的产业预测或投资判断。性能验证记录环境、资料规模、耗时及调用量，准确率和速度依据实测结果填写。

### 3.2 变更确认

T0组织确认用户任务、模板、资料和验收条件。范围、资源或里程碑发生变化时，记录原因、影响、负责人、决定及版本，并同步设计、实现、测试、报告与PPT。表中列出的是学期目标，不表示功能均已实现。

# 4 技术方案与Harness框架参考

### 4.1 当前实现

浏览器提交JSON后，Server检查路由与请求，Service校验主题及资料ID，Store通过SQLite保存资料和报告。Generator执行确定性摘录或一次兼容模型请求，成功后保存Markdown、警示和原文快照。列表仅返回元数据，完整原文按ID读取。

### 4.2 从单次调用到可恢复流程

![图2 目标报告生成流程与执行支撑；为本项目设计，不是已实现功能](../../../assets/opening/harness-plan.png){width=75%}

参照[R2]分章生成Markdown，另行保存资料和图表数据。人工确认内容后选择版式导出PDF，并记录内容、资料、模板及产物版本。切换版式时不重新生成结论，执行状态由Harness管理。

参考检索按类型和章节返回结构、写法及图表规范，附来源、页码与片段ID。返回内容设长度限制；无匹配结果时提示，参考结论不作为当前事实。

参照[R1—R3]保留产物、错误、用量与持久化检查点，重启后从存储恢复，不仅依靠内存状态。

### 4.3 失败与依赖

章节生成失败时保留已完成产物，从未完成步骤继续；输入或模板发生变化时，相关旧产物失效。仅对明确可安全重试的失败进行有限重试。请求超时不能证明供应商尚未执行，结果不明时先由人工确认，避免重复付费。

业务基线使用Python、SQLite与原生Web。渲染需验证中文和分页，生成文本不直接执行。材料构建与业务依赖分别管理；真实模型、完整恢复和产业效果仍待验证。

### 4.4 可参考的框架与取舍

**DeepSeek Harness（dsh）[R6]**：官方项目基于Cordis，采用插件化架构，可参考其工具扩展和执行轨迹。Node.js运行及插件接入如何与当前Python后端衔接、能否适配GLM API，均需实测。开发者预览存在兼容性变更，尚未确定采用该框架。

**LangGraph [R3]**：可参考图状态、持久化检查点和人工介入机制，并作为Python方向的对照候选。内存检查点不保证重启恢复，需验证持久化存储。

**Deep Agents [R7]**：基于LangGraph，提供文件系统、上下文管理和自定义工具等能力。先参考其工具与资料组织方式，与简单固定工作流比较后决定是否采用，不扩大本期范围。
