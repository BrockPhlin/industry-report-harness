# 第11组中期系统设计报告框架

本组提交《产业智能报告生成系统 · 系统设计报告》v1.1。组员修改时先更新 [正文源稿](report.md)，再从仓库根目录运行 `python3 -B tools/midterm/build_design_report.py`，同步生成可编辑 TeX、矢量图和 PDF。正式文件采用 A4 版式，封面和目录同页，正文另起页码。课程规定正文限 15 页、10,000 字，末页标注 LibreOffice Writer 实际统计。[课程评分细则](../../../materials/references/课程报告与评分细则.md#section-05)

| 正文页 | 读者应能说明的事情 | 可以核对的材料 |
| --- | --- | --- |
| 1 · 用户任务与范围 | 解释为什么先做光伏，以及制造产量和新增装机为什么各自需要原文。 | 三项指标、原文段落和验收表。 |
| 2 · 系统架构与两种研究任务 | 限定资料的固定简报与从问题出发的联网研究分别怎样生成和交付。 | [两条路径的图源](figures/workbench-architecture.tex)、[联网试写原稿](../evidence/工作台联网研究_2024年制造与价格.md)。 |
| 3 · 把同一条证据接入两套框架 | 同一指标分别通过 DeepSeek SDK 的 MCP 工具和 Pi 的 CLI 扩展返回。解释试验为什么用模拟端点，以及它能检验什么。 | [DeepSeek 收据](../evidence/deepseek-harness.json)、[Pi 收据](../evidence/pi-cli.json)。 |
| 4 · 固定简报怎样处理一次工具调用 | 结合一个装机指标，说明请求与回传如何对应、谁决定补查、怎样保留缺项与冲突。 | [章内分支的图源](figures/section-flow.tex)、[许子萌的技术稿](../briefing/许子萌_中期技术供稿.md)。 |
| 5 · 工具接口与写作协议 | 能区分两个入口的修订方式；由同学选定的参考报告如何影响提纲和相关章节的写法。 | 核心接口表、工作台写作参考记录。产业统计须独立回查证据。 |
| 6 · 数据、恢复与运行边界 | 知道来源链接、指纹、解析记录、引用、检查点和确认稿各存什么，中断后重跑哪一章。 | 数据结构表、中期 E8。 |
| 7 · 同一题，拿掉装机资料后怎样写 | 看同一栏，比较资料齐全和缺来源时写了什么。区分真实模型运行与离线复跑。 | 中期 E7 两份工具记录，中期 E9 郭润航的独立复跑样张。 |
| 8 · 从草稿原句核对到发布原文 | 说明审阅台怎样定位引用，如何处理明确错配、证据不足和语义推断。 | 16.2% 与 39.6% 的分母反例、12 条定向用例。 |
| 9 · 计划执行、交接与剩余工作 | 交代开题后的范围变化，六位成员交给了谁、后续任务由谁负责。 | PR #10–#13、后续拟定日期。 |
| 10 · 需求追踪、风险与核验责任 | 把四项需求对应到模块与验证，指出尚未测量的部分。 | 需求—模块对应表，AI 使用及人工核验说明。 |

归档中的中期 E1–E9 覆盖多种验证环境。E4 和 E5 运行实际框架并使用本机模拟模型；真实 GLM 联调见 E7。主程序用 LangGraph 管理固定章节的分支，按章恢复和人工确认由项目代码实现。写作参考可选入提纲、分配给相关章节；评价写法时，两稿固定题目、提纲、来源版本、证据、模型及篇幅，只在写作阶段改变是否附摘记；检索变化另记。中期 E9 与补充 E9 分属不同目录，前者为同学独立复跑，后者为构造资料冲突的试验。[中期证据](../evidence/README.md) · [补充验证](../../03-final/evidence/README.md)
