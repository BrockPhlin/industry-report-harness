# 第11组中期系统设计报告框架

写给老师和助教看的系统设计报告。材料以2024年中国光伏产业简报为主线，用同一个案例交代功能、架构、验证和分工。每一节写到能够回查文件、命令或运行记录为止。

按课程细则，正文上限为15页、10000字。封面和目录合页，正文另起页码。提交入口以课程通知为准。 [系统设计报告评分细则](../../../materials/references/课程报告与评分细则.md#section-05)

## 正文组织

| 章节 | 写清什么 | 图表或核对依据 |
| --- | --- | --- |
| 1. 设计概述、需求与范围 | 用户是撰写产业简报的人。开题面向多类报告，中期先把光伏的制造与价格、发电新增装机两章做完整。列出必查指标、人工确认和导出要求。标出已完成与计划中的功能。 | 开题与中期范围对照、当前需求表。 |
| 2. 总体架构与框架选择 | 分别写清 JSON 模板及资料、Python CLI、LangGraph、GLM、Markdown、章节检查点和 Typst 的职责。说明参考 DeepSeek Harness、Pi CLI、chat-demo 的具体机制。 | 总体架构图。两个框架的工具接入验证见 E4、E5。 |
| 3. 核心流程 | 用发电新增装机走一遍，写清模型发工具请求、证据回传、缺项补查、生成、核对及确认导出。补查从已输入的资料里找。 | 一条核心流程图，标出资料齐全和缺失两条分支。E1、E2、E7。 |
| 4. 模块接口与数据设计 | 列出 `run`、`search_evidence`、`inspect`、`approve` 的输入、输出和错误。说明章节、来源、指标、调用记录、检查点和核对件的存储关系。注明模型凭据由本地环境提供。 | 核心接口表、数据结构表。 |
| 5. 本组设计与动机 | 从三个具体问题解释设计：数字容易脱离原文、缺资料却看不出来、长报告中断后重复调用。相应写证据与写作分离、缺项随报告保留、按章恢复。 | 完整与缺装机两份同栏样张、阻断后恢复的运行记录。E7、E8。 |
| 6. 需求、实现和测试对照 | 每条需求对应代码模块、验证输入、预期和实际观察。分别列模拟工具测试和真实模型联调。写明报告版本，以及冲突、超时和风电验证的时间边界。 | 需求—模块—验证表。封版后的 E9–E12 另作进展。 |
| 7. 进度变化、分工与下一阶段 | 回应老师的三条建议，按 Agent 的流程说明分工。写清为什么先限定范围、实际交接发生在哪、下一阶段谁负责。参考报告检索工具写成设计与验证计划。 | 有记录的 PR 或组内交接、待办责任人和预定日期。 |
| 8. AI 使用及来源 | 交代 AI 辅助整理资料、检查实现说明与润色讲稿。组员用源码、原文和实际运行核对数字与结论。列官方文档、证据索引和公开统计出处。 | DeepSeek/Pi 官方文档、中期证据索引。 |

## 写稿时保留四项边界

- 主流程用 LangGraph 编排章内检索、补查和成稿。恢复与人工确认由项目代码实现。
- E7 是真实 GLM 联调。E4、E5 使用本地模拟模型。E8 是主动中断进程，E10、E11 是不同的超时测试。
- 参考报告用于组织章节与图表表达。参考检索工具尚未接入，效果留待同源对照。
- 风电只验证第二个固定输入能复用流程。缺项、冲突和来源可追溯各有单独证据。
