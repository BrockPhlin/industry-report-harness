# 第11组中期 PPT 内容框架

这是组内对齐用的内容顺序。组长兼主讲人 **程文博**。组内后续决定页数、排版和素材位置。课程安排为展示7分钟、问答3分钟。建议先按六段讲稿计时，再决定哪些内容合页。

| 内容段 | 让听众记住什么 | 可用素材及准备人 |
| --- | --- | --- |
| 为什么先做光伏 | 老师建议收窄题目。用组件产量588 GW与新增装机2.78亿千瓦解释口径和出处为什么重要。中期先做两章。 | 两个官方数字和原文定位，崔大元核对。 |
| 回应框架调研 | DeepSeek Harness 用 MCP 接工具，Pi 用 CLI 扩展注册同一个工具。两项测试确认查询结果能回到模型。chat-demo 提供交互参考。项目主流程是 LangGraph 和真实 GLM。 | 用简图画“工具请求 → 证据 → 第二次请求”。E4、E5，许子萌整理。 |
| 系统怎么走完一份报告 | 模板规定必查项，资料工具给出处，系统检查缺项和生成草稿，人确认后导出。 | 从总体架构图取一条光伏路径，田亦洁和许子萌复核。 |
| 本组设计与动机 | 数字容易脱离原文，所以直接用证据字段写入；资料不足易被忽略，所以把待核实保留到 PDF；长报告中断会重跑，所以按章保存。 | 两份 PDF 同栏对照作为主证据，恢复记录用一行概括。李佳雨、郭润航复核。 |
| 拿什么证明已经做成 | E7 完整资料3项、缺装机1项待核实。E8 主动停进程后跳过第一章。模拟工具接入与真实模型结果各标明环境。 | 两份 GLM 样张、已保存的运行记录。提前检查文件可本地打开。 |
| 六人交接与下一阶段 | 用装机指标走过任务定义、资料、编排、审阅、复跑和验收。封版后有冲突、超时和风电验证。参考报告检索工具是下一项尝试。 | 真实 PR 或交接记录，程文博汇总；组员各自准备问答。 |

## 选素材的标准

- 两份实测样张尽量看同一栏，同时保留来源编号和待核实字样。
- 正式主线只讲光伏。“数据冲突怎么处理”“同一流程能否复用”可用封版后证据回答。
- 图上写结论与证据，过程细节由程文博讲。技术图要能看出工具、模型、程序、人工各做什么。
- 每项实测注明环境。两项框架探针用本机模拟模型，E7、E8 使用真实 GLM。封版后试验的错值与超时都按实际注入方式说明。
